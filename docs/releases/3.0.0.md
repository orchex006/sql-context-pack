# 3.0.0 — release and migration notes

3.0.0 implements [Requirement v1.1](../spec/design-spec-v1.1.md): sensitive data must never
reach an AI model, so it can never be retained or used to train one. Protection happens in
the service, in code, before a value is returned over MCP/HTTP or written to an export.

## Why the major bump

Query Data output changes meaning, and some queries 2.1.0 accepted are now rejected.

### 1. Values that 2.1.0 returned are now fake, aliased, generalized or redacted

2.1.0 classified columns by exact English names and treated anything unrecognised as public.
Measured on 2.1.0, `FIRST_NAME`, `LNAME`, `FARMER_NAME`, `PWD`, `TOKEN`, `ADDR`,
`LATITUDE` and free text in `REMARK` were all returned raw. 3.0.0 adds Thai/AgriMap and
abbreviated name rules, reads SQL Server `sys.sensitivity_classifications`, and scans every
string for embedded personal data.

| Class | 3.0.0 output |
|---|---|
| Password, secret, token, key, biometric, unknown lineage | `[REDACTED]` |
| First name / surname / full name | fake Thai or Latin name (title kept) |
| Thai national ID | fake, same layout, valid check digit, leading `0` |
| Phone, bank account, card number | fake digits, same layout, leading `0` |
| Email, username | `user_…` alias (`@example.invalid` for email) |
| Address | `[ADDRESS]` |
| Date of birth | year only |
| Precise location | one decimal place (~11 km) |
| Free text, other strings, JSON | embedded PII replaced in place |

The same real value maps to the same fake within one query (or one export snapshot), so joins
and grouping still work. Query keys are random per query and never stored.

### 2. Results are marked

`QueryResultColumn` gains `sensitivity`, `treatment` and `marker`; `QueryDataResult` gains
`protected_value_counts` and `reveal_handoff`. The Markdown header shows the marker, e.g.
`| ID | FIRST_NAME ⟨FAKE:PERSONAL_NAME⟩ |`. A public column in which a value was replaced is
marked `⟨SCANNED⟩`. **Migration:** a client that matched header text exactly must allow the
marker suffix, or read `columns[].display_name`.

Export samples mark their headers the same way and JSON samples add `column_markers`.
Personal data in routine string literals and table descriptions becomes
`[REDACTED:<CLASS>]`; reports add `pii_literals_redacted`.

### 3. Protected columns cannot be used to infer values

A protected column may only be selected as a plain projection. Using it in `WHERE`,
`JOIN … ON`, `GROUP BY`, `ORDER BY`, `HAVING`, a window, `CASE` or any function — directly or
through an alias — now returns `QUERY_SENSITIVE_USAGE_RESTRICTED` (403) with a
`reveal_handoff`. **Migration:** filter on keys and other public columns instead.

### 4. Real values go to the user, not the model

`reveal_handoff` (`model_may_view: false`) carries the SQL and the steps for the user to run
it themselves. New owner CLI options:

```bash
sqlctx query --reveal --profile <profile> --sql-file query.sql
```

`--reveal` prints real values only to an interactive terminal after the user types the
profile name; it refuses piped, captured or agent-run execution and is not reachable through
MCP or HTTP. `--sql-file` reads the SELECT from a file.

## Not changed

No MCP tool was added or removed. Output format stays `2`; the managed header is unchanged.
`masking_policy` remains `strict`.

## Known limits

- Classification is rule-based. A personal name in a column with a neutral name and no
  title (e.g. `NAME_TH` holding a person's name) is not detected; mark such columns with SQL
  Server data classification (`ADD SENSITIVITY CLASSIFICATION`), which 3.0.0 reads.
- Free-text scanning finds structured PII and titled names, not every untitled name in prose.
- `--reveal` trusts the operating system's interactive-terminal check; it stops ordinary
  agent execution, not a user who deliberately wires a pseudo-terminal into an agent.
- What a model provider does with data it receives cannot be controlled by code. Run hosts
  under terms that exclude training on inputs (commercial/API, Team or Enterprise plans, or a
  consumer account with training turned off) as a second layer.

## Upgrade

```bash
sqlctx doctor update --host <codex|claude|gemini|agy> --version 3.0.0
sqlctx doctor check --host <host>
```

Re-export existing context so samples and routine bodies are produced under 3.0.0 rules.
