# 2.1.0 — release and migration notes

2.1.0 is the first release under the `AGENTS.md` development workflow and the baseline for
everything after it. The 1.x line remains readable history, not an active contract.

## Why the major bump

Two changes alter behaviour for a client that worked against 1.6.0. Neither is a silent
change, and both fail loudly rather than doing something unexpected.

### 1. `sqlctx_sync_context_index` gained `mode`

`mode` defaults to `inventory`. A 1.6.0-era caller that submitted **owner-sourced**
classifications without specifying a mode is now rejected by request validation with
`owner-sourced classifications require owner mode`, rather than prompting for approval.

**Migration:** pass `mode="owner"` on any sync that carries
`classification_source="owner"`, sets `active=false`, or supplies `complete_catalog_id`.
Everything else can stay as it is and will run unattended.

The owner CLI (`sqlctx context-index sync-plan`) picks the mode from the payload
automatically and reports it, so no CLI invocation needs to change.

### 2. Query Data rejects three previously accepted constructs

| Construct | Now |
|---|---|
| `FOR XML ...`, `FOR JSON ...` | `QUERY_PROHIBITED_CONSTRUCT` |
| `WITH (TABLOCKX \| UPDLOCK \| HOLDLOCK \| NOLOCK \| INDEX(...))` | `QUERY_PROHIBITED_CONSTRUCT` |
| `OPTION (...)` | `QUERY_PROHIBITED_CONSTRUCT` |
| `CURRENT_USER`, `SYSTEM_USER`, `SESSION_USER`, `USER` | `QUERY_FUNCTION_NOT_ALLOWED` |

**Migration:** select the columns directly instead of shaping the result server-side. Row
limits and per-column masking then apply normally. Hints have no read-only-safe use here:
they need only SELECT permission, which is exactly why `assert_query_read_only` could not
prove them safe.

`CURRENT_TIMESTAMP`, `GETDATE()`, `TOP`, `OFFSET`/`FETCH`, CTEs, window functions, set
operations, and every previously allowed function are unaffected.

## New

### `agy` (Antigravity) host

`--host` accepts `codex|claude|gemini|agy`. Antigravity is Google's successor to Gemini CLI,
which stopped serving consumer accounts in June 2026.

```bash
sqlctx doctor update --host agy
sqlctx doctor check --host agy
```

Antigravity has no plugin or extension CLI. Installation is file placement at
`~/.gemini/config/skills/sql-context-pack/` plus a merge into
`~/.gemini/config/mcp_config.json`. The merge is additive in both directions: other MCP
servers survive install, update and removal.

`--host gemini` is unchanged. Installing one host does not install or affect the other.

### Version-pinned updates

```bash
sqlctx doctor update --host agy --version 2.1.0
```

A version that does not exist as a tag is a stop that reports the available tags. It never
falls back to the latest release.

### Cross-platform service

```bash
sqlctx service status
sqlctx service start
```

There is one service instance per machine. Every harness session connects to it through its
own stdio bridge; these commands never start a second instance.

| Host | Supervisor |
|---|---|
| Windows with the SCM service registered | Windows Service |
| Windows without it | portable pidfile supervisor |
| Linux with systemd | `systemd --user` unit |
| macOS with launchctl | launchd user agent |
| Anything else | portable pidfile supervisor |

`install.sh` is the POSIX installer; Windows keeps `install.ps1` because SCM registration
needs a service account and ACLs.

## Fixed

- `scripts/validate_manifests.py` had a hardcoded `VERSION = "1.3.0"` while every shipped
  surface was at 1.6.0, so it was validating against a version nothing used. It and the
  version contract test now derive the expected version from `src/sqlctx/_version.py`, and
  both cover the Claude and Antigravity marketplaces.
- The Antigravity marketplace pointed at the pre-transfer repository; it now points at
  `orchex006/sql-context-pack`.

## Operational note

`.agrimap-agent/` was removed from published Git history and is now ignored. If you have a
clone or fork from before this release, re-clone rather than pulling: the history was
rewritten and your local `main` will not fast-forward.
