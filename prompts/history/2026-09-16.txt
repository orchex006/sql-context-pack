# sql-context-pack 1.3.0 — SQL Server analysis failures (OUTPUT param, @@PROCID, scalar function)

- Status: FACT (reproduced live, 2026-09-16, Asia/Bangkok)
- Source: investigation in `agmws-license-management-netcore`, session 093878fe
- Applies to: installed plugin/service `sql-context-pack` **1.3.0**, engine `sqlserver`
- Upstream repo: `D:\Projects&_ArgiMap\Projects\AgriMapPlatform\skills\sql-context-pack`
  (repo `pyproject.toml` declares `product-version = 1.5.0`; **1.5.0 has not been retested** — verify first)

## 1. Symptom

`sqlctx_create_catalog` discovers every requested object, then `set_materialization_selection`
returns `completed_with_warnings` with a non-zero `analysis_failed_object_count`. Failed objects
are silently absent from both sitemap views and from `get_materialization_plan` — they are not
reported as excluded, and **no MCP surface names them or gives a reason**.

Observed on a 37-object request: `discovered 37 / fully_analyzed 19 / analysis_failed 18`.

## 2. Minimal reproducers (all verified individually, one object per catalog)

Baseline controls that **pass**:

    CREATE PROCEDURE [agrimap_app].[ZZ_SQLCTX_PROBE_CREATE] @PI_X INT = NULL
    AS BEGIN SET NOCOUNT ON; SELECT @PI_X AS X; END

Repro A — `OUTPUT` parameter; Repro B — `@@PROCID`; Repro C — any scalar function.
Each of A, B, C fails alone: `discovered 1 / fully_analyzed 0 / analysis_failed 1`.

## 3. Ruled out by the reporter

objects missing from DB; missing VIEW DEFINITION; WITH ENCRYPTION; CREATE vs CREATE OR ALTER
declaration form; profile allowed_object_types missing FUNCTION; batch/concurrency effect;
environment regression.

## 4. Required outcomes

1. A, B and C each analyze and materialize successfully on `sqlserver`.
2. Parameter direction (`OUTPUT`) is preserved in v2 managed output and in table/routine metadata.
3. Scalar functions analyze and materialize; `object_types: [function]` stops being
   advertised-but-broken.
4. Regression tests covering all three repros.
5. **Separately**: per-object failure reporting. `get_catalog_status` must expose a `failures[]`
   list (object id, stage, error code, safe message), or an equivalent MCP/CLI surface.

## 5. Non-goals

- No change to masking, approval gates, write scopes, or routine deployment semantics.
- Do not "fix" this by making analysis failures silent or by auto-excluding failed objects.
- No change to the project's SQL Server objects; the legacy procedures are valid T-SQL.
